# deploy/ - all cloud and environment configuration

Everything you edit to run the platform somewhere lives under this folder.

```
deploy/
├── local/                     run everything on your machine with Docker Compose
│   ├── docker-compose.yml     backing services + all services + web apps
│   ├── .env.example           copy to .env (gitignored): passwords, keys, ports, Stripe, mail
│   ├── secrets/               JWT signing keystore (gitignored; made by scripts/generate-keystore.sh)
│   ├── postgres/init/         first-start SQL: one database and role per service
│   └── scripts/               keystore, DB snapshot, bootstrap and release helpers
├── aws/                       run it on AWS (EKS, RDS, MSK, CloudFront...)
│   ├── config.example.env     copy to config.env (gitignored): region, domain, size, Stripe, Google
│   ├── deploy.sh / destroy.sh the single entry points
│   ├── terraform/             infrastructure
│   ├── helm/ecommerce/        workloads; values.yaml holds per-service sizing and settings
│   ├── k8s/                   database bootstrap Job, secret store
│   ├── docker/                the one Dockerfile used for every service image
│   └── lib/                   script internals
└── ci/                        deploy.sh used by the pipeline
```

## Which file do I edit?

| I want to change... | Local (Compose) | AWS |
|---|---|---|
| Passwords, JWT keystore password, internal token, data keys | `local/.env` | generated by Terraform into Secrets Manager (`<project>-<env>/app`, `/db`); the JWT keystore is created by `deploy.sh` |
| Stripe keys and webhook secret | `local/.env` (`STRIPE_*`) | `aws/config.env` (`STRIPE_*`) |
| Google sign-in | `local/.env` (`GOOGLE_*`) | `aws/config.env` (`GOOGLE_*`) |
| Mail provider | `local/.env` (`MAIL_*`; default is the Mailpit container) | Amazon SES, created by Terraform (no setting needed) |
| Ports | `local/.env` (`*_PORT`) | not applicable (ClusterIP services behind one load balancer) |
| Domain and hostnames | not applicable (`localhost`) | `aws/config.env` (`DOMAIN_NAME`) |
| Size, replicas, autoscaling | not applicable | `aws/config.env` (`SIZE_PROFILE`) and `aws/helm/ecommerce/values.yaml` |
| Region, API access, alerts | not applicable | `aws/config.env` |
| A service's own tunables (timeouts, limits, pool sizes) | environment variables listed in `services/<name>/.../application.yml` (`${VAR:default}`) | `aws/helm/ecommerce/values.yaml` (`env:` per service) |

Two things deliberately stay beside the code because their tools require it:

- **Frontend build variables** (`VITE_*`) live with each app: `apps/admin-product-catalog/.env.example`.
  For AWS, `deploy.sh` sets them from your domain at build time.
- **Per-service defaults** stay in each service's `application.yml`, next to the code that reads them.

## Where to start

- Local: [getting-started](../docs/getting-started.md), then `cp deploy/local/.env.example deploy/local/.env`.
- AWS: [cloud setup](../docs/guides/cloud-setup.md) first (account, quotas, domain, Stripe, Google), then
  [deploy-aws](../docs/guides/deploy-aws.md) and `cp deploy/aws/config.example.env deploy/aws/config.env`.
- Every variable, its default and whether production needs it: [environment variable catalogue](../docs/reference/environment-variables.md).
  It is generated from the code; after adding or changing a variable run
  `node deploy/local/scripts/env-reference.mjs` (CI runs it with `--check`) and describe the new variable in
  [env-descriptions.json](../docs/reference/env-descriptions.json).
- How a value travels from config to a pod: [diagram 17](../docs/architecture/diagrams/17-configuration-flow.md).
- Third-party setup (Stripe, email, Google): [integrations](../docs/guides/integrations.md).

## Secrets

`local/.env`, `local/secrets/` and `aws/config.env` hold real secrets and are gitignored; only the
`*.example` templates are committed. Never put a real key in a template.

## Moved from `infra/`

This folder replaces the old top-level `infra/` directory. Commands now read
`docker compose -f deploy/local/docker-compose.yml ...` and `./deploy/local/scripts/...`. The Compose
project name is unchanged, so your existing containers and volumes are picked up as before.
